## Approved business rules and technical contract

- User selected VND/manual payments and partial payments no greater than outstanding balance. Each receipt number is globally unique; full receipt reversal retains history/reason. Cancellation only when effective payments total zero (2026-10-04).
- Payment UUID, normalized receiptNumber (2–32 Unicode characters, existing six-whitespace trim and ROOT uppercase), immutable chargeId/amount/currency/recordedAt/createdAt, RECORDED/REVERSED, rowVersion, reversedAt/reversalReason/updatedAt. Amount uses the same positive exact integer VND/range as 4B1. Server recordedAt uses current clock; no future/backdated settlement, gateway, refund transfer or reconciliation system.
- POST requires chargeId, receiptNumber, amount and expectedChargeVersion. Charge must be OPEN; no active Student/fee check for settling a retained obligation. Reject amount above outstanding. Every successful payment or reversal advances charge version, even when timestamps coincide; no persisted balance/counter or new PAID charge status.
- PUT requires status=REVERSED, expectedVersion (receipt), expectedChargeVersion and reason (2–500 trimmed Unicode characters). REVERSED is terminal; original receipt number cannot be reused. Charge, amount/currency and original timestamps are immutable. Reversal restores outstanding balance; no partial reversal. Reason is stored on receipt, not copied into audit metadata.
- Lock charge → payment, always refresh cached entities. Cancellation uses the same charge lock before SUM of RECORDED payments. Separate charges can proceed independently; unique receipt index handles cross-charge duplicate races. All supported writes/audit share one transaction; payment/reversal each writes one PAYMENT event (RECORDED/REVERSED), charge version is returned through balance/read rather than generating a second event.
- Balance reads return amount, paidAmount, outstandingAmount, currency, status and rowVersion from one query/snapshot joining charge to RECORDED receipts. OPEN outstanding equals original amount minus paid; CANCELLED retains original amount but has zero collectible outstanding and zero effective paid. No multiple-query torn version/balance response. Overpayment/cancellation are application transaction invariants; direct SQL bypass is unsupported and not audited.
- ADMIN /api/v1/admin/finance/payments POST, GET/list, GET/{id}, PUT/{id}; GET /charges/{id}/balance. Bounded pagination, literal q on receiptNumber, chargeId/status filter; receiptNumber/amount/status/recordedAt/createdAt/updatedAt sorts + UUID tie-breaker, default recordedAt,desc. Same safe error contract and unique Bearer OpenAPI schemas.
- V22 owns payment columns/defaults/nullability/PK/charge FK/amount+currency+status+version+reversal-shape CHECKs, receipt uniqueness, charge/status index; extends Finance audit policy to PAYMENT without weakening FEE/CHARGE rules. Exact V21 entity scan retains 24; V22 validates 25 on exact upgraded schema with Flyway disabled.
