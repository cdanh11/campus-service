## Notification technical contract (5A)

- Notification owns template, notice, per-account delivery and audit tables. Template has UUID, normalized unique code (2–32), name (2–160), title (2–160), plain-text body (2–4000), ACTIVE/INACTIVE, nonnegative rowVersion and timestamps. Trim exactly the existing six boundary whitespace characters; count Unicode code points.
- ADMIN creates a DRAFT notice from an ACTIVE template, retaining immutable template UUID and title/body snapshot. Draft may be edited with expectedVersion and published once. Publishing requires explicit 1–100 distinct ACTIVE account IDs; no broadcast enumeration, external email or hidden recipient expansion. PUBLISHED content is immutable; no physical deletion or expiry.
- Deliveries retain UUID, noticeId, recipientId, UNREAD/READ, deliveredAt, readAt, rowVersion and timestamps; one delivery per notice/account. Receipt owner comes from authenticated principal; forbidden UUIDs are not exposed through inbox/read queries. Repeated read returns the retained READ record without duplicate event/version increment. No caller-selected recipient in self-service writes.
- HTTP: ADMIN templates and notices create/get/list/PUT; POST notice/{id}/publish with expectedVersion and recipientIds. Authenticated /api/v1/notifications inbox, GET delivery/{id}, PUT delivery/{id}/read with expectedVersion. Responses use stored PostgreSQL precision. Safe errors and Bearer OpenAPI follow established contracts.
- Audit captures actor, resource/type/target/action/version/time and status-only object metadata atomically. Failed publish must leave no partial deliveries/status/audit. Failed read audit rolls back acknowledgement. Domain ownership stays explicit; IdentityUserDirectory gains a narrowly scoped active-account read operation implemented inside Identity.
- V23 is new; freeze historical V22 entity scan to its original 25 entities before adding Notification entities. Upgrade test applies exactly V23 on a populated V22 database, preserves baseline/history, checks actual columns/defaults/PK/FK/unique/CHECK/indexes via SQLSTATE writes and Hibernate validate on the exact upgraded public schema with Flyway disabled. No create/update behavior.
