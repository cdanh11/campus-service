## 4A1 contract and implementation plan

- Separate Dormitory-owned building, room and bed tables. UUID, code (2–32 PostgreSQL/Unicode characters), label/name (2–160), ACTIVE/INACTIVE, BIGINT nonnegative row version, creation/update timestamps. Room has immutable buildingId; bed has immutable roomId. No extra capacity counter, floor/gender policy or organization coupling.
- Trim exactly space, tab, newline, carriage return, vertical tab and form feed; normalize codes with Locale.ROOT uppercase and validate after expansion. SQL uses the identical six-character boundary whitespace set. Building code globally unique; room code unique within building; bed code unique within room, case-insensitively in SQL.
- New inventory is ACTIVE and requires active ancestors. Parent locks acquired building → room → bed. Inactive ancestors prohibit activation/creation below them. Building/room cannot be deactivated while it has active immediate children; deactivate children first. No physical delete or cascaded status changes. Assignment-specific occupied-bed rules arrive in 4A2 before allocations exist.
- ADMIN routes `/api/v1/admin/dormitory/buildings`, `/rooms`, `/beds`, with POST/GET/list/PUT; resource selection is fixed, not an arbitrary client table/type. PUT does not accept parent changes. Create parentId only for room/bed. No unaudited HTTP mutation path.
- q literal case-insensitive code/name matching (max 100 characters); page ≥ 0, size 1–100, page×size ≤ Integer.MAX_VALUE; status and parent filters; allowlisted sort plus ID ascending tie-breaker. Error envelope follows existing APIs.
- Audit owns actor FK, resource/type/target/action/version/time and status-only object JSONB, with no invented JSON length cap or polymorphic target FK. An audit failure rolls back business mutation and versions. No new audit read API.
- Add domain boundary tests; per-resource route authorization, successful mutation, stale/duplicate/reference/query rollback, audit failure, update races and parent close/create race tests; actual V18→V19 fixtures/history preservation, full new schema constraints/defaults/FKs/indexes and Hibernate validate on exact upgraded schema with Flyway disabled. Freeze V18 historical entity scan before new entities exist.
